事故复盘｜三套检测器的原始告警都在，复盘人员却不能确认是告警策略不稳，还是某个采集域发生了误标。请实现内部安全运营用的校准审计器。样本是合成事故，每条有来源组、输入分数向量、当前标注及生效范围。工具不探测真实系统，也不训练分类模型。

规则只能从输入给定的整数候选阈值中选择，规则按固定优先级触发，具备「两个指标同时越线」和显式的冲突处理。对某个基准策略及候选策略，每条告警是否挡住真实事件、是否造成误升级、是否越过同一严重度边界，都要给出触发规则。不同来源可以给同一事件贴不同标签，允许最多一个采集域不可信。对每个允许的不可信域，忽略来自该域的可争议标记，剩余标记按批次去重，事件真值可取任一个仍受支持的标记；没有支持时两种真值都纳入审查，不允许逐个统计指标选择一套有利真值。已人工复核的固定标注不参与丢弃或改写。处置预算按时间窗和事件故障域统计，重复事件只算一次，以最早入窗时间为准。

fit 找一套固定阈值，对全部允许的资料解释满足各故障域「严重漏报上限」和全局误升级上限。接着最小化最坏的越级次数、相比基线改动的阈值数和阈值元组。若无解，返回一个经过证明的最小不可解除约束集，包含极小的含义由固定降序删除法定义。review 单独评估给定阈值，给上界及可重放的真值见证，并找状态从基线变为目标策略后第一次违反的规则。支持 20 条规则、每条 5 个阈值、300 条事故和 6 个证据域，按实际行为等价的阈值段压缩，说明最坏情形组合如何共享，给小输入独立穷举验证。至少测试采集域失效造成临界例翻转、同事故重复占窗口、单个局部最优联动导致无解、原标注冲突仅在一域失效后消除、以及全局最坏见证不可由局部最坏拼凑。

可验收输出为 python -m alert_calibration <命令> CASE.json 的 UTF-8 JSON。空仓库、Windows 原生 Python 3.12、标准库和 CPU 即可交付；随代码给本地合成回放、完整 README 和可用 unittest discover 执行的断言。输入非法时标明结构字段及原因。
